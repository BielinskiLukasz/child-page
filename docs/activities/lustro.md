# Lustro

Status: implemented

- Issue: [#213](https://github.com/BielinskiLukasz/child-page/issues/213)
- Planned activity id: `lustro`
- Planned CSS prefix: `lu-`

## 1. Overview

Lustro (`lustro`, module `js/lustro.js`, CSS prefix `lu-`): a big outline of a butterfly, a house or a tree is split by a soft dashed centre line. The child paints with a finger on either half and the same line appears at once on the other half, mirrored, in the same colour and width.

## 2. Business purpose

Gentle introduction to symmetry through free drawing: every picture comes out symmetrical and pretty. It fills the gap between Malowanie Światłem (fading light) and Rysuj Kształty (tracing): paint stays on the picture.

## 3. Activity flow

1. One outline (random from a shuffled bag of three) is shown with a row of six colour dots (one chosen at random) and a sponge button. 2. The child paints on either half; each stroke is mirrored over the centre line and clipped to the outline. 3. When about 40% of the outline is painted the picture glows for 3 s, then fades out (0.3 s) and the next outline fades in (0.5 s) on a clean canvas. 4. The sponge button wipes the picture with a 0.5 s fade. The activity never ends by itself.

## 4. Rules and behavior

| Item | Value |
|---|---|
| Outlines | butterfly, house, tree, each drawn in a 100x100 unit space symmetrical about x = 50; bag of three shuffled, each once before repeats (the first of a new bag is never the one just shown) |
| Board | square, at least 300 px on a 320 px wide portrait phone and 304 px on 568x320 landscape (at least 60% of the shorter side) |
| Brush | width max(14 px, 5% of the board); round caps; same colour and width on the mirrored side |
| Colours | six dots (red, orange, yellow, green, blue, purple), 56 px, each with its own white pattern (stripes, dots, zigzag, checks, waves, cross); the chosen dot has a thick ring; the first colour is random |
| Wipe | round 56 px sponge button; 0.5 s fade of the paint, then empty canvas; ignored while the picture glows |
| Clip | paint is clipped to the outline path and never leaves it |
| Goal | painted area measured on a 40x40 grid of the cells inside the outline (a cell counts when the brush centre passes within half the brush width; the mirror counts too); at 40% the glow starts |
| Glow | 3 s static warm drop-shadow, painting ignored; then 0.3 s fade-out, new outline, 0.5 s fade-in |
| Pointers | only the first pointer paints; other fingers are ignored until it lifts |

No score, no failure, no stored data, no text on screen.

## 5. Educational and developmental benefits

Symmetry (what is done on one side appears on the other), cause and effect, colour choice, fine motor control with a finger.

## 6. Accessibility and usability

The board is focusable: arrows move a brush ring (3% of the board per press), Enter or Space paints while held (arrows then draw a line), colour dots and the sponge button are reachable by Tab (Enter/Space selects). The pattern on each colour dot and the ring on the chosen dot are the non-colour cues. All targets are at least 56 px; aria labels are in Polish.

## 7. Risks and limitations

Checked only with a node stub DOM (stroke flow, coverage, glow, bag, wipe, two pointers) and syntax checks; no browser or device run was possible, so the real proportions of the outlines, the clip and the glow still need a manual look. Painting 40% of a small outline can be quick for a child who scribbles.

## 8. Configuration

None; no setting. Enabled by default and appended at the end of the menu list.

## 9. Assets

Inline SVG outlines as path strings in `OUTLINES` (the butterfly's left half is generated by mirroring its right half), a canvas for paint, menu icon in `js/activities.js`. No sound, no external files.

## 10. Randomization and variants

Outline order: shuffled bag of three. Starting colour: random on every mount.

## 11. Progression and difficulty

None: the same rules throughout.

## 12. Completion and feedback

At 40% painted: glow for 3 s, then the next outline on a clean canvas. Sponge: fade and clean canvas.

## 13. Analytics and metrics

Each stroke start (touch or Enter/Space): `track('interaction', {variant: 'butterfly' | 'house' | 'tree'})`; each glow-and-next picture: `complete()`. Wipes and colour changes are not reported. Open-ended.

## 14. Technical implementation

`mount` builds the DOM, attaches the root with `container.appendChild(root)` before `layout()` and returns a cleanup that cancels the rAF loop, removes the window and document listeners and the root. Strokes are kept as arrays of points relative to the board plus colour and relative width; `clipAndRedraw()` resizes the canvas, clips it to the scaled outline path (`Path2D`) and replays every stroke (and its mirror), so rotation or resize loses nothing. Fast drags are filled with points every 1% of the board so the line and the coverage grid have no holes. A single rAF loop (dt capped at 0.05 s, running only while a fade or the glow is active, paused while the tab is hidden) drives the wipe, glow and outline fades through inline opacity, so it also works under prefers-reduced-motion.

## 15. Responsive layout and coordinate system

Portrait: board over the controls (4 + 3 grid of 56 px buttons); landscape: board left, controls in a 3-column grid on the right, 72 px left padding keeps the Back button uncovered. Board size is pure CSS (`min(width, height minus reserved)`); SVG sizing uses `.stage .lu-svg` and `.stage .lu-dotsvg`.

## 16. Error and edge-case handling

Rotation and resize: the canvas is replayed from relative strokes. Tab hidden: the current stroke ends and the loop pauses. Two fingers: second pointer ignored. Very fast touches: each pointer-down starts one stroke, gaps are filled. Focus lost with a key held: the stroke ends. Painting while the glow runs: ignored. A cap of 6000 points per picture prevents unbounded growth.

## 17. Testing

Manual scenarios: (1) Open: one outline with a dashed centre line, six dots, a sponge; one dot is chosen. (2) Draw on the left half: the mirrored line appears at the same moment on the right, in the same colour; draw across the outline edge: paint stays inside. (3) Pick another colour and draw: the new colour is used, the old paint stays. (4) Rotate the device: the picture stays, redrawn. (5) Touch with two fingers: only the first paints. (6) Tab to the board, move with arrows, hold Enter and press arrows: a mirrored line is drawn. (7) Fill about 40%: the picture glows for 3 s, then a different outline fades in clean; repeat three times: all three outlines appear before one repeats. (8) Press the sponge: the paint fades in 0.5 s. (9) Settings, Statystyki: strokes counted as touches, glow-and-next pictures as completions.

## 18. Known limitations and open issues

The brush width is computed when a stroke starts (at least 14 px at that time); after rotating to a smaller board it is clamped to 14 px. No eraser, saving or sharing (out of scope). No real-device verification.
